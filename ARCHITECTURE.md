# Claude Bridge — архитектура и полное техническое описание

Резюме программы: зачем она нужна, из чего состоит, как устроен каждый компонент, какие
протоколы связывают части и как обеспечивается безопасность. Документ отражает фактическое
состояние Windows-версии (ветка `feature/windows-multi-agent`). Ссылки D-n / P-n / H-, M-, L- —
решения и находки из реестра `docs/specs/2026-10-31-windows-opencode-adaptation-inventory.md`.

---

## 1. Что это и зачем

**Claude Bridge** — связка «Node.js-мост на Windows-ПК + Android-приложение», которая
**зеркалирует терминальные сессии агентов программирования и позволяет управлять ими со
смартфона**: Claude Code, opencode и любой TUI-агент (адаптер `generic`).

Агент работает на ПК со всем доступом к файлам, git и тулчейнам; телефон — второй терминал той же
сессии: одна общая псевдоконсоль Windows (ConPTY), а не копии.

Сценарии:

- **Зеркало сессии.** `claude-mobile` (агент по умолчанию) или `claude-mobile --agent opencode` —
  та же сессия открыта на телефоне; печатать можно с обоих устройств.
- **Удалённый запуск.** С телефона — новая сессия выбранного агента с его опциями (телефон передаёт
  только id опций, P-3) в разрешённом каталоге.
- **Запросы разрешений.** Агент спрашивает разрешение — на телефон приходит уведомление с кнопками
  из `choices` адаптера («Да / Всегда: … / Нет», D-4, D-23.6); ответ уходит агенту семантически.
- **Подтверждение операций владельца.** Выпуск кода сопряжения и включение интернет-доступа
  подтверждаются на уже сопряжённом телефоне с контрольным кодом (D-13, D-22).
- **Голосовой ввод** — запись на телефоне, распознавание (faster-whisper) на ПК.
- **Вне сети ПК** — p2p-туннель (iroh, QUIC) без проброса портов и VPN.

**Скоуп (D-9):** внутренняя утилита команды; каждый ставит её на свой личный рабочий ПК; только
Windows-хост; без Linux-режима и обратной совместимости. **Модель угроз (D-8):** личный ПК, одна
учётная запись, физический доступ только у владельца — **не для общих компьютеров**. Защищаются сеть
телефон↔ПК и браузер/интернет-код на ПК; вредоносная программа под учётной записью владельца — вне
модели.

Сквозные принципы: не ломать рабочую функциональность; fail-closed в спорных местах безопасности;
секреты — в профиле пользователя (`%LOCALAPPDATA%`, закрыт ACL от других учётных записей), а не в
рабочей копии git.

## 2. Топология

```
   ┌──────────────────────────── ПК (Windows 10/11) ─────────────────────────────┐
   │  Задача Планировщика «ClaudeBridge» (при входе пользователя, не служба)      │
   │  или ярлык в shell:startup (запасной путь, D-25.4)                           │
   │     └─ node start-bridge.js ─► node server.js (отсоединён, без консоли)      │
   │            │  HTTPS/WSS :8790 — 127.0.0.1 + LAN-адрес (host:"auto")          │
   │            │  UDP :8791 — маяк · mDNS claude-bridge-<fp8>.local              │
   │            │  HTTPS/WSS 127.0.0.1:8792 — вход интернет-туннеля               │
   │            ├─ keeper.js (по одному на сессию) ═ named pipe + HMAC ═ ConPTY   │
   │            │        └─ claude.exe / opencode.exe --server … / generic         │
   │            ├─ адаптеры: claude (хуки) · opencode (SSE + API) · generic       │
   │            ├─ фоновый сервис opencode (opencode service, общий, D-12)        │
   │            ├─ stt.py (py -3.11, faster-whisper)                              │
   │            └─ claude-tunnel.exe listen (Rust, iroh p2p)                      │
   │  claude-mobile (attach.js) ── WSS 127.0.0.1:8790, токен владельца + пиннинг  │
   │  bridge-hook.js (хук Claude Code) ── POST /hook, токен хука + пиннинг        │
   └─────────────────────────────────────┬───────────────────────────────────────┘
                                         │ LAN (Wi-Fi)          Интернет (p2p)
                                         ▼                           ▼
   ┌──────────────────────────── Телефон (Android 8+) ───────────────────────────┐
   │  BridgeService (foreground): OkHttp WSS ── мост :8790 (пиннинг)              │
   │     ├─ NSD (mDNS) + UDP-проба :8791                                          │
   │     └─ claude-tunnel connect (libclaudetunnel.so) ── p2p до ПК               │
   │  LocalGateway 127.0.0.1: :38471 UI из assets · :38472 ws-прокси              │
   │  MainActivity (WebView + xterm.js) ── http://127.0.0.1:38471                 │
   └──────────────────────────────────────────────────────────────────────────────┘
```

Два пути до моста:

1. **LAN:** телефон нашёл ПК по mDNS/UDP и подключается к `wss://<LAN-адрес>:8790`. Приоритетный путь.
2. **Интернет (p2p):** ПК не виден в сети — пара `claude-tunnel connect` (телефон) ↔
   `claude-tunnel listen` (ПК) поверх iroh; телефон подключается к `wss://127.0.0.1:<порт туннеля>`,
   сайдкар пробрасывает байты на loopback-порт `8792` моста. Требует `libclaudetunnel.so` в APK
   (на 2026-10-31 не собрана — §12).

В обоих случаях WebSocket идёт по **TLS с пиннингом самоподписанного сертификата** моста
сквозным образом от WebView до моста; туннель добавляет шифрование iroh. Путь (2) не обязательно
прямой: iroh использует preset N0 — публичные discovery- и relay-серверы Number 0 (n0); при
невозможности прямого соединения трафик идёт через relay. Содержимое relay не видит, но оператор
видит метаданные (IP-адреса, NodeId, время, объём) — аудит L-15.

## 3. Мост на ПК (каталог `bridge/`)

### 3.1 Каталог данных (`lib/datadir.js`, P-1)

Всё состояние — в `%LOCALAPPDATA%\ClaudeBridge` (тесты — `CLAUDE_BRIDGE_HOME`): `config.json`,
`pairings.json`, `internet.json`, `owner.token`, `certs\`, `sessions\`, `logs\`, `bin\` (шим от
установщика). Права — ACL профиля пользователя (D-8), без `chmod`. Полная раскладка — §10.

### 3.2 Запуск и автозапуск (P-4, D-25.4)

- `install.ps1` регистрирует задачу Планировщика «при входе пользователя» в его сеансе (служба не
  подходит: session 0 ломает ConPTY). Если задачу зарегистрировать не удалось, или с ключом
  `-StartupShortcut`, — ярлык `ClaudeBridge.lnk` в `shell:startup` с тем же действием (окно
  свёрнуто). Действие — `node start-bridge.js`: он поднимает `server.js` отсоединённым процессом
  (`detached`, `windowsHide`, `stdio: 'ignore'`) и выходит.
- Повторный запуск при работающем мосте — no-op: второй экземпляр выходит по `EADDRINUSE` до любых
  побочных эффектов (маяк, туннель, keeper'ы).
- Консоли у моста нет: `console.*` дублируется в `logs\bridge.log` (`lib/log.js`, ротация при 5 МБ
  в `bridge.log.1`, переводы строк и управляющие символы в сообщениях экранируются).
- Перезапуск моста **не** убивает сессии: они живут в отдельных keeper'ах.

### 3.3 `server.js` — ядро

Слушает:

| Сокет | Адрес | Назначение |
|---|---|---|
| HTTPS/WSS | `127.0.0.1:8790` и LAN-адрес `:8790` (`host:"auto"`) или `host` из конфига | UI, WS, `/pair`, `/stt`, `/hook`, `/health` |
| UDP-маяк | `*:8791` | ответ на broadcast `CLAUDE_BRIDGE?` |
| HTTPS/WSS туннеля | `127.0.0.1:8792` | трафик из интернет-туннеля (тот же обработчик) |

Владелец отличается по `localPort === port` и loopback-адресу: трафик туннеля приходит на 8792.

#### Конфигурация (`config.json`)

```json
{
  "port": 8790, "host": "auto",
  "defaultAgent": "claude",
  "agents": { "claude": {}, "opencode": {} },
  "defaultCwd": "~", "projects": [],
  "env": {}, "scrollbackBytes": 1048576, "mdnsName": "claude-bridge",
  "sttPython": "py", "sttPythonArgs": ["-3.11"], "sttModel": "large-v3", "sttLanguage": "ru"
}
```

- Создаётся из `config.example.json` (установщиком или при первом старте). Пути: `~`, `%VAR%`,
  `/` и `\`; относительные пути отбрасываются.
- `agents.{id}.{type,name,command,prefixArgs,args,scroll,serviceFile}` (D-15.4); без ключа `agents` —
  `claude` и `opencode`, если найдены. `claudeCommand`/`claudeArgs` больше не читаются (D-9).
- `env` целиком попадает в окружение сессий. Порт можно переопределить `CLAUDE_BRIDGE_LISTEN_PORT`.
- Без ключа: `scrollbackBytes` — 256 КБ, `maxSessions` — 24, `sttMaxQueue` — 4. `mdnsName` — имя
  mDNS-сервиса (имя хоста mDNS от него не зависит, см. «Обнаружение»).

#### TLS (`lib/cert.js`, P-4)

Сертификат создаётся без openssl: PowerShell `New-SelfSignedCertificate` в `Cert:\CurrentUser\My`
(срок 10 лет) → `Export-PfxCertificate` со случайным паролем (`certs\bridge.pass`) → `bridge.pfx` +
`bridge.cer` (DER) → удаление из хранилища Windows. **Отпечаток** — SHA-256 от DER; его пиннят
телефон, `claude-mobile` и хук (M-8), он же — идентификатор ПК в приложении.

#### Кто есть кто (P-1, D-1, D-16)

1. **Владелец** — loopback + основной порт + `Authorization: Bearer <owner.token>` (`claude-mobile`)
   или cookie `bridgeToken` с **браузерным токеном** (браузер ПК). Токен владельца — 32 случайных
   байта hex в `owner.token`, постоянный; `claude-mobile --rotate-token` перевыпускает его, мост
   закрывает соединения кодом 4401.
2. **Устройство** — токен, выданный при сопряжении; в `pairings.json` только SHA-256 (`tokenHash`,
   D-15.7), публичный id — первые 12 hex хэша. Сверка — за постоянное время.
3. **Хук сессии** — `CLAUDE_BRIDGE_HOOK_TOKEN` в окружении агента: только `POST /hook` своей сессии
   (`X-Bridge-Session`).

- **Origin** (P-1, второй слой против H-1): WS и HTTP — только с `https://127.0.0.1:<port>`,
  `https://localhost:<port>`, `http://127.0.0.1:38471` (WebView) или без `Origin` (CLI). Allowlist
  `Host` не вводится (D-16.4).
- **Вход браузера** (L-9, D-16.1, D-18.2): `claude-mobile --open` → одноразовый токен (60 с) →
  `GET /?ott=…` (только loopback, основной порт) → HttpOnly-cookie с браузерным токеном (живёт в
  памяти до ротации/рестарта) → redirect на `/`. Ссылка печатается только в интерактивную консоль.
- **Граница модели (D-16.3, D-22.1):** агент под той же учётной записью может прочитать
  `owner.token` и meta других сессий; от «самоподтверждения» защищают D-13 и хэши токенов устройств;
  агент, который правит файлы моста и перезапускает его, — вне модели D-8.

#### Сопряжение (P-7, P-9, D-13, D-22)

- Код выпускается **только по запросу владельца** (`claude-mobile --qr` → `pairinfo`), не при
  старте: 5 случайных байт (10 hex, 40 бит), живёт 10 минут, одноразовый. Перебор: 5 ошибок с адреса
  → блок `/pair` на 15 минут; не более 50 ошибок на код.
- QR `{cb:1, host, port, code, fp}` — единственный способ (H-2): ручного ввода кода в приложении нет.
- `POST /pair` — только основной порт (не туннель), тело ≤ 4 КБ; ответ — токен, отпечаток, порт,
  p2p-адрес (если интернет включён).
- **Подтверждение выпуска кода** (= подтверждение сопряжения, D-15.6) и **включения интернета**:
  если сопряжённых устройств ещё не было — вопрос `[y/N]` в интерактивной консоли `claude-mobile`
  (`confirmRequired` → повтор с `confirmed:true`); иначе — только на сопряжённом телефоне
  (`confirmRequest` с 4-значным `checkCode`, тот же код в консоли — `confirmPending`; запрос живёт
  2 минуты, `lib/confirmations.js`). После отказа/истечения — пауза для действия 1 мин, ×2 до
  15 мин; ожидание снимается при отключении запросившего (`confirmClosed`) — это тоже включает паузу.
- После первого сопряжения `phoneRequired:true` в `pairings.json` закрывает консольный путь навсегда
  (сброс — удалить `pairings.json` при остановленном мосте). Повреждённый `pairings.json` — мост не
  стартует (fail-closed). Отзыв устройства рассылает информационное уведомление остальным.

#### Сессии и keeper'ы (D-7, D-11, P-3, D-21)

- `createSession`: агент — из реестра адаптеров; опции устройства нормализуются до объявленных
  адаптером id со значением строго `true` (P-3); сырые `args` и произвольная `command` — только
  владельцу.
- Каталог: канонизация `lib/paths.js` (`realpathSync.native`, `path.relative`, сравнение без учёта
  регистра); с телефона отклоняются UNC, `\\?\`, `\\.\` и `C:foo`. Каталог устройства вне `projects`
  → `defaultCwd` (D-21, поведение OT-11).
- Resume при живой сессии того же агента в том же каталоге → `createConflict`, повтор с `force:true`
  (D-7, D-15.2).
- Лимиты: `maxSessions` (24), не более 10 созданий в минуту на устройство.
- keeper запускается `detached + windowsHide`; meta `sessions\<id>.json` хранит имя pipe
  `\\.\pipe\claude-bridge-<32 hex>`, секрет keeper'а (64 hex), токен хука и состояние адаптера.
  Окружение агента: окружение моста + `config.env` + `CLAUDE_BRIDGE_SESSION`,
  `CLAUDE_BRIDGE_HOOK_TOKEN`, `CLAUDE_BRIDGE_PORT`, `CLAUDE_BRIDGE_CERT_FP` + добавка адаптера;
  `CLAUDE_BRIDGE_KEEPER_SECRET` keeper удаляет из окружения до запуска агента.
- **Рукопожатие (D-11):** pipe доступен по SMB, поэтому keeper ничего не отдаёт (даже `hello`) и не
  принимает команд, пока клиент не докажет знание секрета (HMAC-challenge); keeper доказывает то же
  мосту. После рестарта моста секрет берётся из meta; `restoreSessions` переподключается с
  повторами до 30 с (M-6).
- Scrollback: буфер на сессию (`scrollbackBytes`); размер PTY «следует за тем, кто печатает».
- ConPTY: агент Claude включает win32-input-mode (`\x1b[?9001h`); после него одиночный Esc теряется,
  поэтому Esc в PTY пишется в кодировке win32-input-mode (D-23.1, `lib/win32-input.js`).

#### Адаптеры агентов (`agents/`, D-3, P-2, D-15.3)

Контракт (`agents/index.js`): `id, name, options[], scroll ('wheel'|'pageKeys', D-10),
events ('hook'|'sse'|'none'), available(), spawnSpec(), isResumeLike(), onHook(), onInput(),
subscribe(), reply()`. События адаптера (`status`, `request`, `requestClosed`, `notify`) применяет
`lib/session-events.js`.

| Адаптер | Запуск | События | Ответ |
|---|---|---|---|
| `claude` | `claude.exe` напрямую (за npm-шимом `claude.cmd`; без шима — `claude.exe` из PATH, D-19.5); опции `resume`, `skipPermissions` | хуки: `PermissionRequest` → запрос (мгновенно); `Notification[permission_prompt]` — запасной и после рестарта моста (D-23.4); `PreToolUse`/`PostToolUse`/`UserPromptSubmit` → `working`; `Stop` → `idle` + «готово»; `idle_prompt` игнорируется (D-23.5); события с `agent_id` статус не меняют | клавиши `1` / `2` / Esc (win32-input-mode); кнопки — только для белого списка инструментов (D-19.4); «Всегда» — при непустом `permission_suggestions`, подпись конкретизируется (D-23.6); очередь FIFO (D-19.3) |
| `opencode` | фоновый сервис (`service.json`, Basic-авторизация; не отвечает — `opencode service start`); сессия — `POST /api/session` с `location.directory` и (опция `askShell`, D-14) `permissions`; TUI `opencode.exe --server <url> --session <id>` с `OPENCODE_PASSWORD` | SSE `/api/event` с фильтром по `sessionID`, включая дочерние сессии субагентов (D-23.3); после переподключения — ресинхронизация разрешений | `POST /api/session/{id}/permission/{requestId}/reply` с `{decision}`; 404 = уже закрыт |
| `generic` | `command`/`args` из конфига | нет (только зеркало) | нет |

Запрос → `notify{event:'request', requestId, choices}`; ответ `reply` → `replyResult` (`ok` /
`stale` / `failed`); закрытие — `requestClosed` (ответ с любого клиента или любой ввод в PTY, кроме
пассивного: фокус, колесо, ответы терминала — D-19.1). Переподключившийся клиент получает повтор
всех ожидающих запросов (D-20). Текст для человека очищается от невидимых/bidi символов, длинное
значение — «начало…конец (N симв.)» (D-19.2, `lib/display-text.js`). Сессии opencode после `kill`
не удаляются в сервисе (D-15.11).

#### Хук Claude Code (`hooks/bridge-hook.js`, P-4, P-6)

Регистрируется установщиком (`tools/install-hooks.js`, набор событий — `tools/hook-settings.js`) в
`%USERPROFILE%\.claude\settings.json` exec-формой
`{"type":"command","command":"node","args":["<repo>\\bridge\\hooks\\bridge-hook.js"]}` (строковая
форма шла бы через Git Bash) на событиях `PreToolUse`, `PostToolUse`, `PostToolUseFailure`,
`PermissionRequest`, `PermissionDenied` (`matcher: "*"`), `Notification`, `UserPromptSubmit`, `Stop`;
слияние с хуками пользователя и бэкап файла (`settings.json.bak-<время>`, хранятся 5 последних;
запись через временный файл с повтором `rename` (EPERM/EBUSY), временный файл убирается; при
  сбое `settings.json` не меняется); `install-hooks.js status`
— код 0, если хук установлен. Вне bridge-сессии хук молча выходит; в сессии — `POST /hook` с токеном
хука и пиннингом сертификата. Хук никогда не мешает Claude: код выхода 0, пустой stdout, ошибки
проглатываются.

#### Голосовой ввод — `POST /stt`

Владелец или устройство; очередь ≤ `sttMaxQueue` (4) → 503; загрузка сразу на диск (`%TEMP%`),
лимит 20 МБ → 413; постоянный воркер `stt.py` через `sttPython` + `sttPythonArgs` (`py -3.11`),
таймаут 180 с; клиенту — обобщённая ошибка без путей.

#### Интернет-доступ (p2p iroh)

- Флаг `internet.json`; включение — только владельцем после подтверждения (см. «Сопряжение»),
  выключение — без подтверждения.
- Сайдкар `bridge\bin\claude-tunnel.exe listen --target 127.0.0.1:8792 --secret-file
  certs\iroh.key --allow-file certs\tunnel-allow.txt`; allowlist — NodeId сопряжённых устройств
  (телефон регистрирует свой NodeId сообщением `registerNode`). Нет бинаря — интернет-доступ
  недоступен (`internet.available:false`).
- Перед стартом — `taskkill /IM claude-tunnel.exe /F` (бесхозные туннели прошлых запусков); при
  падении — рестарт через 3 с; при выходе моста туннель гасится.

#### Отзыв устройства — `revokeDeviceById`

Удаляет устройство из `pairings.json`, переписывает allowlist, рвёт его WS (`close(4401)`),
перезапускает туннель, уведомляет оставшиеся устройства. Последующие попытки подключения с
отозванным токеном получают HTTP 401 ещё до WS-апгрейда — телефон трактует это так же, как
`close(4401)`.

#### Обнаружение в сети (P-7, D-17, D-18)

- `host:"auto"`: `lib/lan.js` выбирает частный адрес физического адаптера (виртуальные и VPN —
  vEthernet/WSL/Hyper-V/VirtualBox/VMware/Radmin/ZeroTier/Tailscale — по имени отбрасываются);
  мост слушает только `127.0.0.1` и этот адрес (не `0.0.0.0`, L-11). Адрес перепроверяется каждые
  15 с; без сети мост предупреждает и не выдаёт QR с `127.0.0.1`.
- **mDNS** (`lib/mdns.js`): имя хоста `claude-bridge-<fp8>.local`, A-запись — только слушаемый адрес,
  без IPv6, TXT `fp`.
- **UDP-маяк** (8791): на `CLAUDE_BRIDGE?` отвечает `{claudeBridge, port, fp}` без имени ПК, только
  частным адресам; сокет без `reuseAddr`.

#### Заголовки безопасности статики

CSP заголовком (`default-src 'self'`, `script-src 'self'`, `connect-src` к loopback ws/wss,
`object-src 'none'`, `frame-ancestors 'none'`), `X-Frame-Options: DENY`, `nosniff`,
`Referrer-Policy: no-referrer`; путь статики — `path.normalize` + `startsWith(WEB_DIR + sep)`.
Статика и `/health` — только владельцу или устройству.

#### Устойчивость (P-10)

Проверка типов всех входов (`lib/validate.js`; M-2, L-1, L-2, L-8: управляющие и bidi-символы
вырезаются); авторизация до апгрейда WS, `maxPayload` 4 МБ, не более 64 WS-клиентов (M-3);
исключения адаптеров не роняют мост.

### 3.4 `keeper.js` — хранитель сессии

Отсоединённый процесс без консоли, владеет одной ConPTY (`node-pty`) и переживает перезапуск моста.
Сначала слушает pipe, затем запускает агента (pipe занят — агент не стартует). Держит свой
scrollback. Протокол — JSON-строки после рукопожатия: вход `in` / `resize` / `kill`, выход
`hello` (буфер, размер, pid) / `out` / `exit`. Одиночный Esc из `in` перекодирует в win32-input-mode
(D-23.1). Любая ошибка — причина в `logs\keeper-<id>.log`, meta удаляется, процесс завершается.

### 3.5 `attach.js` (`claude-mobile`) — CLI на ПК

Локальный клиент: `wss://127.0.0.1:<port>/ws` с токеном владельца и пиннингом `certs\bridge.cer`.
Вызывается через шим `claude-mobile.cmd` (§3.7).

| Команда | Действие |
|---|---|
| `claude-mobile [args…]` | новая сессия агента по умолчанию в текущем каталоге; аргументы — агенту |
| `claude-mobile --agent <id> [args…]` | новая сессия указанного агента |
| `claude-mobile -l` / `-a [id]` | список сессий / подключение |
| `claude-mobile --device` | устройства: отзыв, интернет-доступ (только TTY) |
| `claude-mobile --qr` | QR сопряжения (только TTY, с подтверждением) |
| `claude-mobile --open` | веб-интерфейс в браузере по одноразовой ссылке |
| `claude-mobile --rotate-token` | перевыпуск токена владельца |

- Raw-режим консоли; `Ctrl+\` — отсоединиться (сырой `0x1c` или нажатие в win32-input-mode, D-23.2,
  пакет агенту не пересылается).
- При выходе из raw-режима пишет `CONSOLE_RESET` (`lib/win32-input.js`, D-25.5): выключает режимы,
  которые агент мог включить в консоли пользователя через свой вывод, — `?9001` (win32-input-mode),
  `?1004` (фокус), `?1000/?1002/?1003/?1006` (мышь), `?1049` (альтернативный экран); всё обёрнуто в
  сохранение/восстановление курсора `ESC 7 … ESC 8` (D-26.5), иначе `?1049l` вне альтернативного
  экрана переносит курсор в начало. Тест — `test/attach-detach.test.js`.
- Изменение размера — событие `resize` stdout (на Windows нет `SIGWINCH`).
- Конфликт resume — вопрос в консоли и повтор с `force` (D-7).

### 3.6 `stt.py` — распознавание речи

Постоянный воркер `faster-whisper` (модель `large-v3`, CPU, int8), модель грузится один раз.
Протокол — JSON-строки stdin/stdout. VAD-фильтр против галлюцинаций на тишине, `initial_prompt` для
пунктуации, повторный проход, если длинный текст вернулся без знаков препинания.

### 3.7 Установщик (`install.ps1`, `uninstall.ps1`, `bridge/tools/`)

  Планировщика `ClaudeBridge` (AtLogOn, Interactive, Limited, без ограничения времени работы,

## 4. Интернет-туннель `claude-tunnel` (каталог `tunnel/`, Rust)

Sidecar на Rust (`iroh 1.0.2`, QUIC). Один бинарь, три подкоманды. Собирается и
как ПК-бинарь (`bridge\bin\claude-tunnel.exe`, `x86_64-pc-windows-msvc`), и как
Android-.so (`libclaudetunnel.so`, `aarch64-linux-android`) — Android запускает его
как обычный процесс. Оба собираются `tools/release.ps1` (`cargo build --release --locked`);
сборка `.so` требует Android NDK и на 2026-10-31 не выполнялась (§12).
Профиль release: `opt-level="z"`, `lto`, `strip`, `codegen-units=1`.

ALPN протокола: `b"claude-bridge/1"`.

### 4.1 Подкоманды

- **`listen`** (сторона ПК): принимает iroh-соединения, каждый bi-stream
  пробрасывает на локальный TCP-таргет (`127.0.0.1:8792` — порт моста).
- **`connect`** (сторона телефона): локальный TCP-listener; каждое TCP-соединение
  форвардит как bi-stream по единственному (лениво устанавливаемому,
  авто-переподключаемому) iroh-соединению.
- **`id`**: печатает NodeId этого ключа и выходит (телефон так узнаёт свой
  постоянный NodeId для регистрации в allowlist). Важно: печатает **ровно тот**
  id, что предъявит `connect` (`endpoint.id()`) — на Android «короткий» путь из
  публичного ключа расходился с `endpoint.id()`.

### 4.2 Постоянный ключ (`load_or_create_secret`)

ed25519-ключ хранится в файле (`%LOCALAPPDATA%\ClaudeBridge\certs\iroh.key` на ПК,
`files/iroh_phone.key` в приложении).

**Windows (P-4):** файл открывается с `FILE_FLAG_OPEN_REPARSE_POINT` — симлинк или иная
точка повторного анализа открывается сама и отвергается по атрибутам этого хэндла (вместо
`O_NOFOLLOW`); не обычный файл — отказ; права не меняются (защита — ACL профиля, D-8); новый ключ
создаётся `create_new` и наследует ACL каталога.

**Unix (Android)** — логика чтения усиленная (fail-closed, без TOCTOU):

- Файл открывается **ровно один раз** с флагом **`O_NOFOLLOW`** (симлинк →
  ошибка ELOOP): кража секрета = кража p2p-личности.
- Все операции (`stat`/`chmod`/чтение) идут **по этому fd**, а не по имени —
  подмена пути между проверкой и использованием исключена.
- Если права слишком открыты (`mode & 0o077 != 0`) — ужесточаются до `0600`
  через тот же fd (`fchmod`); **если ужесточить не удалось — отказ использовать
  ключ** (а не чтение как есть).
- Принимается как сырые 32 байта, так и hex (64 символа).
- Новый ключ создаётся `create_new(true).mode(0o600)`.

### 4.3 `listen` — сторона ПК

- **Fail-closed по умолчанию:** без `--allow-file` и без явного `--allow-any`
  слушатель **отказывается стартовать** — иначе он пробрасывал бы любой узел
  интернета на порт, дающий сетевое доверие.
- `endpoint.online().await` — ждёт готовности relays/discovery, чтобы ticket был
  полным; печатает `{event:"ready", ticket, node_id}`.
- Лимиты анти-амплификации: `MAX_CONNS = 32` (семафор), `MAX_STREAMS_PER_CONN =
  64` (семафор на соединение). Превышение — соединение/поток отбрасывается.
- **Таймаут рукопожатия 5 с:** slow-loris-пир иначе держал бы слот соединения до
  исчерпания лимита.
- **Транспортная авторизация:** `node_allowed()` сверяет `conn.remote_id()` с
  allowlist. Проверка — **при установке соединения И на каждый новый bi-stream**:
  если узел отозвали (мост переписал allow-file), новые потоки уже не пройдут и
  соединение закрывается. Отсутствующий/нечитаемый allow-file → **никого**
  (fail-closed).
- Каждый принятый stream → `TcpStream::connect(target)` + двунаправленная
  перекачка `pump`.
- `monitor_paths` следит за путями iroh (direct / relay / mixed, RTT) и шлёт
  события `path` — телефон показывает, как именно установлена связь.

### 4.4 `connect` — сторона телефона

- Парсит ticket → `EndpointAddr`; постоянный secret_file даёт стабильный NodeId.
- `ensure_conn`: одно общее iroh-соединение с backoff-переподключением
  (1 с → ×2 → максимум 15 с, таймаут dial 20 с), никогда не сдаётся.
- На каждое входящее TCP-соединение (от `LocalGateway`) — `open_bi`, до 5 попыток
  с инвалидацией мёртвого соединения, затем `pump`.
- `pump`: `tokio::io::copy` в обе стороны; TCP EOF → `send.finish()` +
  `stopped().await` (дожидается флаша); stream EOF → `shutdown` TCP-записи.

## 5. Android-приложение (каталог `android/`)

Пакет `com.q.claudebridge`, `minSdk 26`, `targetSdk 34`, без сторонних UI-фреймворков.
Зависимости: OkHttp 4.12 (TLS/WSS), Play Services code-scanner (QR). Нативный
UI собирается кодом (без layout-XML). Web-интерфейс терминала берётся из общего
`bridge/web` (Gradle-таски `syncWebAssets` / `syncVendorAssets` копируют его и
xterm в `assets/web` перед сборкой). `versionName "0.2.0"`, `versionCode 2` (D-25.2); release
подписывается ключом команды, `debuggable false` (§9.3).

### 5.1 `MainActivity` — экраны и WebView (≈1100 строк)

Единственная активность (`singleTask`, `exported=true` для интентов из
уведомлений). Три состояния:

1. **Экран блокировки** (если включена биометрия и требуется вход).
2. **Экран сопряжения** (нет ни одного ПК).
3. **Основной экран** — WebView с терминалом.

#### Защита биометрией

- Флаг `biolock` в prefs. При включении:
  - `FLAG_SECURE` на окне — прячет содержимое из «недавних» и от скриншотов;
  - вход по `BiometricPrompt` (API≥28, `BIOMETRIC_WEAK | DEVICE_CREDENTIAL`) или
    `KeyguardManager.createConfirmDeviceCredentialIntent` (API 26/27).
- **Политика повторного запроса** (`needLock`): запирается, если после последней
  разблокировки **гас экран** (`screenOffSinceUnlock`, статик-флаг, ставит
  сервис по `ACTION_SCREEN_OFF`) **или** прошло больше `LOCK_GRACE_MS` (60 с)
  форы. Свежий процесс всегда запрашивает вход. Закрывает дыру «разблокировал →
  выключил экран → кто-то взял телефон в течение форы».
- Включить `biolock` нельзя без настроенной блокировки экрана
  (`km.isDeviceSecure()`).

#### Сопряжение (P-7, H-2)

- **Только QR** (`startScan`, ML Kit): `{cb:1, host, port, code, fp}`, разбор и проверка —
  `Protocol.parsePairingQr` (отпечаток — 64 hex, `host` — только `[A-Za-z0-9.-]`, `port` 1…65535,
  M-2). Отпечаток получен вне канала → сразу пиннится (`Tls.buildClient(fp)`); QR без `fp`
  отвергается («Это не QR-код Claude Bridge»). Ручного ввода кода и TOFU-сопряжения нет; код не
  отправляется на адрес из обнаружения.
- Диалог «Добавить компьютер»: кнопка «Сканировать QR-код»; найденные в сети несопряжённые ПК
  (`unpairedDiscovered`) показываются только для информации.
- Итог сохраняется в `BridgeStore` (`commitPairing`), новый ПК становится активным, сервис
  переподключается, активность пересоздаётся.
- Сохранённый токен без отпечатка (данные старой версии) — подключение не выполняется, статус
  просит сопрячь заново (`Protocol.credentials` → `REPAIR`, L-17).

#### Мост JS ↔ приложение

- **`AppBridge`** (`@JavascriptInterface AndroidApp`):
  - `openSettings()` — нативный экран настроек;
  - **`wsUrl()`** — `ws://127.0.0.1:<wsPort>/ws?cbnonce=<proxyNonce>`. **Токен в
    JS не отдаётся** — его подставляет нативный ws-прокси; странице достаётся
    лишь nonce запуска (допускает нас к прокси, но сам по себе бесполезен);
  - `copyText` / `pasteText` — системный буфер обмена.
- **`SttBridge`** (`AndroidSTT`): `start`/`stop`/`cancel`/`transcribe` — запись
  `MediaRecorder` (AAC/MP4, 44.1 кГц) в `cache/stt.m4a`, отправка на `/stt` с
  токеном, результат возвращается в JS (`window.sttResult`/`sttError`). Требует
  `RECORD_AUDIO`.

#### WebView — настройки безопасности

- JS включён, DOM-storage включён; **файловый доступ выключен**
  (`AllowFileAccess/ContentAccess/…FromFileURLs = false`) — страница локальная по
  http, доступ к ФС не нужен (защита в глубину).
- **`shouldOverrideUrlLoading`** (обе перегрузки): навигация допускается только
  на `http://127.0.0.1:<uiPort>`; любой другой адрес уходит во **внешний браузер**
  (`ACTION_VIEW`) и в WebView не грузится. Иначе недоверенная страница, открывшись
  здесь, через `AndroidApp.wsUrl()` выманила бы nonce прокси. Стартовая загрузка
  (`loadUrl`) и WebSocket сюда не попадают.
- **`onReceivedSslError`**: доверяем только сертификату с **запиннингованным**
  отпечатком (сверка `Tls.fingerprint(cert)` с `prefs.fp`), иначе `cancel()`.
- `onPageFinished`: если пришёл интент с `session`, дёргает `attach(...)` в JS;
  значение **экранируется** `JSONObject.quote` (защита от инъекции через интент).
- `onReceivedError` (main frame): показывает заставку и повторяет загрузку.

#### Прочее

- `validSession` — сессия из интента должна матчить `[A-Za-z0-9_-]{1,64}`
  (активность экспортируемая — чужое приложение не должно подсунуть мусор).
- `onBackPressed` — сворачивает (`moveTaskToBack`), не закрывает.
- `registerStateReceiver` — приём `ACTION_STATE` от сервиса; на API≥33
  `RECEIVER_NOT_EXPORTED`, на API<33 — защита signature-правом `INTERNAL_PERM`.

### 5.2 `BridgeService` — foreground-сервис (≈1100 строк)

Постоянно живущий сервис (`foregroundServiceType=dataSync`). Держит WS с мостом,
находит мост в сети, показывает уведомления, управляет туннелем.

#### Обнаружение и выбор пути

- **mDNS (NSD)** + **UDP-проба** (broadcast `CLAUDE_BRIDGE?` на 8791). Найденный
  мост идентифицируется по `fp`: обновляется адрес нужного ПК; незнакомые ПК
  копятся в `discovered` для экрана «добавить компьютер».
- **Приоритет LAN.** `lanLastSeen` / `lanGraceUntil`: при старте и появлении WiFi
  даётся фора 12 с на поиск ПК в сети, прежде чем поднимать туннель. Если ПК
  давно (>15 с) не виден в LAN, а пользователь разрешил интернет для этого ПК и
  есть `nodeTicket` — поднимается туннель (`wantTunnel`). Если ПК снова появился
  в LAN, а мы на туннеле — форсированный реконнект на LAN (LAN важнее).
- `MulticastLock` удерживается ради mDNS.
- `registerDefaultNetworkCallback` — при появлении сети пробуем переподключиться.

#### WebSocket

- `connect()` идемпотентен; перечитывает prefs (активный ПК/токен могли
  смениться). Эффективный адрес пишется в `useHost/usePort` (их же читают WebView
  ws-прокси и загрузка аудио).
- URL: `wss://<host>:<port>/ws?token=<token>`; клиент — `Tls.buildClient(fp)`
  (пиннинг, ping 20 с).
- В `onOpen`: запрос `internet`-статуса и `registerNode` (сообщает мосту
  постоянный NodeId телефона).
- В `onMessage` (разбор — `Protocol.java`, JVM-тесты): `notify` → системное уведомление
  (с кнопками по `choices`); `requestClosed` / `replyResult` → снятие уведомления / тост;
  `confirmRequest` / `confirmClosed` → подтверждение D-13; `status: working` → гасит устаревшее
  уведомление сессии; `sessions` → счётчик живых в статусе; `internet` → запоминает ticket ПК.
- Устройство отозвано — `onClosed(4401)` (живое соединение разорвано мостом) или
  `onFailure` с ответом HTTP 401 (новое подключение отклонено до WS-апгрейда, авторизация
  идёт до него): удаляет ПК из списка, «Доступ отозван», переключается на следующий.
  Решение — `Protocol.isRevoked(closeCode, httpCode)` (JVM-тест).
- Backoff переподключения: 2 с → ×2 → максимум 30 с.

#### Постоянная p2p-личность телефона

- `ensurePhoneNodeId`: один раз запускает `libclaudetunnel.so id --secret-file
  files/iroh_phone.key`, парсит `node_id`, сохраняет в prefs. При наличии связи
  сразу регистрирует.
- `ensureTunnel(ticket)`: запускает `…connect --ticket=<value> --listen
  127.0.0.1:0 --secret-file <тот же ключ>`. `--ticket=<value>` одним аргументом,
  чтобы значение не спуталось с флагом (ProcessBuilder без shell). Парсит
  события `ready` (→ порт → `connect()`), `path` (обновляет UI/статус), `error`.

#### Уведомления и экономия батареи

- Два канала: `bridge_status` (IMPORTANCE_MIN, ongoing) и `claude_events`
  (IMPORTANCE_HIGH, вибрация, на локскрине `VISIBILITY_PRIVATE`).
- **Ответ из уведомления** (D-4): кнопки строятся по `choices` запроса (подписи — от моста,
  например «Всегда: доступ к каталогу …»); нажатие (`ACTION_REPLY`) шлёт
  `reply{id, requestId, decision}`, не открывая приложение. `requestClosed` снимает уведомление;
  `replyResult` со `stale` — тост «Запрос уже закрыт — ответ не отправлен».
- **M-4:** на API ≥ 31 каждая кнопка ответа требует разблокировки
  (`setAuthenticationRequired(true)`, всегда, не только при биометрии); на API < 31 «Всегда» не
  показывается (`Protocol.visibleChoices`), а при биометрии кнопок нет вовсе
  (`Protocol.canShowActions`); на локскрине при биометрии контент скрыт (`VISIBILITY_SECRET`).
- **Подтверждение операций владельца** (D-13): `confirmRequest` → уведомление «Claude Bridge:
  нужно подтверждение» с контрольным кодом и кнопками «Разрешить / Отклонить» (API ≥ 31, обе с
  разблокировкой) и диалог в открытом приложении (на API < 31 — только диалог); ответ —
  `confirm{confirmId, allow}`; `confirmClosed` снимает уведомление.
- **Учёт уведомлений** (`RequestNotifications`, D-20, D-23.3): у каждого открытого запроса — своё
  уведомление (сессия + `requestId`; повтор того же запроса — на месте); прочие события сессии —
  одно уведомление на сессию, новое заменяет прежнее; «агент завершил ответ» устаревает при любом
  новом событии; ответ на ПК (`status: working`) снимает уведомление.
- **PendingIntent кнопок** (`NotifIntents`, ревью C-1): всё значимое (сессия, запрос, решение,
  `confirmId`; у тапа и смахивания — случайная эпоха процесса) кодируется в data-URI интента, а не в
  extras: после рестарта процесса кнопка старого уведомления не может отправить ответ новому
  запросу. Уведомления прошлого процесса снимаются при старте сервиса — мост заново присылает
  открытые запросы и подтверждения (D-20).
- **Режимы фоновой связи** (`bgMode`): `always` / `wifi` (в фоне только по WiFi)
  / `app` (только при открытом приложении). `allowedNow()` решает, держать ли
  связь; `pauseConnection()` рвёт её ради батареи.

### 5.3 `LocalGateway` — локальный шлюз для WebView (≈285 строк)

Делает интерфейс **всегда живым, даже когда ПК выключен**. Два TCP-сервера на
loopback (фиксированные порты для стабильного origin → `localStorage`
переживает рестарт):

- **`:38471` — статика** из assets APK (`index.html`, `app.js`, xterm…).
  Отдаёт с теми же CSP/защитными заголовками, что и мост; защита от `..` в пути.
- **`:38472` — ws-прокси**: прозрачный TCP-прокси до моста поверх TLS с
  пиннингом. Адрес моста берётся из prefs при **каждом** соединении (смена ПК /
  переход на туннель подхватываются сами).
- Апгрейд проксируется с заголовком `Origin: http://127.0.0.1:38471` (D-15.12): allowlist `Origin`
  моста не отклоняет WebView, даже если шлюз занял запасной порт. Входящие `Cookie` и
  `Authorization` выбрасываются (ревью M-3) — учётные данные к мосту подставляет только шлюз.

**Модель безопасности прокси** (ключевая):

- Прокси на 127.0.0.1 доступен **любому** приложению на телефоне. Поэтому:
  1. **nonce запуска** (`proxyNonce`, 16 случайных байт): прокси обслуживает
     только запрос, содержащий `?cbnonce=<nonce>` (сверка **постоянного времени**,
     `MessageDigest.isEqual`). Nonce знает лишь наш WebView (через `wsUrl()`);
     чужое приложение подключиться не сможет.
  2. **Токен подставляется нативно** (`injectTokenCookie`): страница токен не
     знает, прокси дописывает `Cookie: bridgeToken=…` в апгрейд-заголовок перед
     форвардингом. XSS в UI не утащит токен — он не покидает нативную часть.
- `readHttpHead` читает заголовок побайтно до CRLFCRLF (лимит 16 КБ), не задев
  тело. `pump` перекачивает байты в обе стороны, TLS-сокет до моста —
  `Tls.socketFactory(fp)` (тот же пиннинг).

### 5.4 `BridgeStore` — реестр компьютеров (190 строк)

Список сопряжённых ПК в `SharedPreferences` (ключ `bridges` — JSON-массив).
Идентификатор ПК — отпечаток сертификата (`fp`). Поля `Bridge`: name, host, port,
token, fp, internet (флаг разрешения p2p), nodeTicket (iroh-адрес моста).

- **Активный ПК** (`activeFp`) определяет, куда подключаются сервис, WebView и
  загрузка аудио.
- **Зеркалирование:** плоские ключи `token/fp/port/host` всегда отражают активный
  ПК — «старый» код продолжает читать их как раньше.
- `migrate()` — старая схема (один ПК в плоских ключах) переезжает в список.
- Операции: `addOrUpdate`, `updateHost` (адрес найденного в сети), `remove` (при
  удалении активного активным становится первый оставшийся), `setActive`,
  `setInternet`, `setTicket`.

### 5.5 `Tls` — пиннинг сертификата (≈95 строк)

- `fingerprint(cert)` — SHA-256 hex от `cert.getEncoded()`.
- `pinnedTrust(fpHex)` — TrustManager, доверяющий **только** серту с данным
  отпечатком; без отпечатка (`null` или пустой) — не доверяет никому (fail-closed, L-17: TOFU нет
  нигде).
- `socketFactory(fpHex)` — сырые TLS-сокеты с тем же пиннингом (для ws-прокси).
- `buildClient(fpHex)` — OkHttp с пиннингом; `hostnameVerifier` всегда true
  (доверие определяет **пиннинг**, а не имя хоста — сертификат самоподписанный на
  CN=claude-bridge, а адрес меняется).

### 5.6 Манифест и сетевой конфиг

- Разрешения: INTERNET, ACCESS_NETWORK_STATE, ACCESS_WIFI_STATE,
  CHANGE_WIFI_MULTICAST_STATE, POST_NOTIFICATIONS, RECORD_AUDIO,
  FOREGROUND_SERVICE(+DATA_SYNC), VIBRATE, USE_BIOMETRIC.
- **`INTERNAL_PERM`** (`signature`-уровень) — защищает broadcast сервис→активность
  от подделки чужим приложением на API<33.
- `allowBackup=false`, `fullBackupContent=false` — токены не утекают в бэкап.
- **`network_security_config`**: cleartext разрешён **только** к `127.0.0.1` /
  `localhost` (локальный шлюз), весь остальной cleartext запрещён
  (`base-config cleartextTrafficPermitted=false`). Связь с мостом всегда TLS.
- **jniLibs**: `useLegacyPackaging=true` — `.so` распаковывается, чтобы её можно
  было запустить как процесс (`exec`).

### 5.7 Чистая логика без Android API (JVM-тесты)

- `Protocol` — разбор `choices`, `replyJson` / `confirmJson`, проверка id запроса/сессии/кода,
  правила M-4 (`visibleChoices`, `canShowActions`), разбор QR, `credentials` (L-17).
- `RequestNotifications` — учёт событийных уведомлений (§5.2).
- `NotifIntents` — data-URI PendingIntent'ов уведомлений (C-1).
- Тесты: `android/app/src/test/java/com/q/claudebridge/` (`ProtocolTest`, `RequestNotificationsTest`,
  `NotifIntentsTest`, `LocalGatewayTest`, `TlsTest`; 37 тестов), запуск — `gradlew testDebugUnitTest`.
  Тестовые зависимости `junit`, `org.json` — только `testImplementation`, в APK не попадают (D-15.8).

## 6. Web-интерфейс терминала (`bridge/web/`, общий для ПК и приложения)

`index.html` + `app.js` (≈1050 строк) + `lib.js` (чистые функции: `filterPaste`,
`scrollSequence`, `buildCreate`, `requestStore`, `buildReply`, `armGuard`, `confirmPrompt`,
`replayGate` и др.; тесты `bridge/test/web-lib.test.js`, связка с DOM-заглушкой —
`bridge/test/web-app-wiring.test.js`) + `style.css`. Внутри приложения грузится локально из assets
(копия `bridge/web`, Gradle `syncWebAssets`); в браузере ПК — с моста после входа по одноразовой
ссылке. Окружение — по наличию `window.AndroidApp`.

### 6.1 Терминал

- **xterm.js** (`@xterm/xterm` + `addon-fit`), тема тёмно-синяя, scrollback 10000.
- Ввод (`term.onData`) → `{type:'input'}`. Локальный экран **зеркалит фактический
  размер PTY** (сервер шлёт `resized`/`scrollback`); свой размер клиент лишь
  «предлагает» (`resize`), сервер применяет его, когда клиент печатает.
- `viewport()` считает cols/rows по фактическому размеру ячейки.

### 6.2 Прокрутка и выделение пальцем (самая нетривиальная часть)

- **Прокрутка:** обычный буфер — листаем scrollback xterm; альтернативный экран — способ
  объявляет адаптер в `sessions[].scroll` (D-10): `wheel` — события колеса SGR
  (`\x1b[<64…M`, Claude Code и opencode), `pageKeys` — PageUp/PageDown (generic по умолчанию:
  системный ConPTY не пересылает включение режима мыши). Отправка — тип `scroll`, чтобы не
  переключать «владельца размера» PTY.
- **Выделение:** долгое нажатие (500 мс) выделяет слово под пальцем, появляются
  два ползунка (`selh`), каждый тянется отдельно посимвольно. Жест
  перехватывается целиком (`preventDefault` на touchstart), иначе нативный
  long-press Android «съедает» палец.
- **Автоскролл у краёв** (`AUTOSCROLL_ZONE = 48`): выделение тянется вслед за
  прокруткой. В альтернативном экране, где историей владеет TUI, применяется
  эвристика `detectShift` — сравнивает снимки видимых строк до/после посланного
  колеса и сдвигает границы выделения на столько же строк, чтобы оно оставалось
  «приклеенным» к тексту.
- Копирование — через `AndroidApp.copyText` (или `navigator.clipboard` в
  браузере); вставка — в поле ввода.

### 6.3 Сессии, ввод, уведомления

- Вкладки сессий (`renderTabs`) с индикатором статуса (🟠 ждёт / 🔵 работает),
  долгое нажатие — завершить/убрать сессию.
- Панель клавиш (Esc, Tab, стрелки, Enter, ^C, вставка) + поле сообщения (Enter
  отправляет текст + `\r`). Вставка (кнопка, поле, терминал), отправляемый текст и результат
  голосового ввода проходят `filterPaste`: управляющие и невидимые символы вырезаются (L-10).
- `notify` → баннер + вибрация + бип (`AudioContext`) + Web Notification (если
  вкладка скрыта).
- Диалог новой сессии: агент (из `sessions.agents`) и его опции-флажки (`options`
  адаптера), каталог из `projects` или свой путь; уходит `create{agent, options}` (P-3).
  `createConflict` (живая сессия этого агента в каталоге при resume) → предупреждение и
  повтор с `force:true` (D-7).
- **Полоса запросов `#reqbar`** (D-24): кнопки ответа на открытые запросы под баннером —
  «сессия: сообщение (+N)» и кнопки с `label` от моста; приоритет у запроса текущей сессии,
  нажатие на текст переключает на сессию запроса; кнопки «взводятся» через 500 мс после смены
  верхнего запроса (защита от двойного тапа).
- В WebView телефона — диалог подтверждения операции владельца (`confirmRequest`, крупно
  `checkCode`; фокус по умолчанию — «Отклонить», «Разрешить» активна через 700 мс, D-22.5);
  во время проигрывания буфера ответы терминала не отправляются (D-19.1).
- В приложении настройки устройств/компьютеров открываются нативным экраном
  (`AndroidApp.openSettings`), в браузере — WS-диалог `devices`.

### 6.4 Голосовой ввод в UI

Долгое нажатие (350 мс) на кнопку отправки → запись (`AndroidSTT.start`), таймер,
захват указателя (палец может дрожать). Отпускание → «Принять» (текст в поле) /
«Ввод» (сразу в Claude). Обработка — `AndroidSTT.transcribe`, результат приходит
в `window.sttResult`.

## 7. Протоколы (сводка)

### 7.1 WebSocket клиент ↔ мост (`/ws`, JSON)

**Клиент → мост:** `create` (`cwd`, `agent`, `options`, `force`; владельцу также `args`,
`command`, `title`), `attach` (id/cols/rows), `input`, `scroll` (не двигает владельца размера),
`resize`, `kill`, `remove`, `list`, `reply` (`id`, `requestId`, `decision`: `once|always|reject`),
`internet`, `registerNode` (только устройство, свой NodeId), `confirm` (`confirmId`, `allow`;
только сопряжённое устройство), только владелец: `devices`, `setInternet`, `pairinfo`
(+`confirmed`), `revokeDevice`, `issueLoginToken`, `rotateOwnerToken`.

**Мост → клиент:** `sessions` (сессии с `agent`, `scroll`; `agents` с опциями; `projects`),
`created`, `createConflict` (`live`), `scrollback`, `output`, `resized`, `exit`, `status`,
`notify` (`event`: `request|done|info`; для `request` — `requestId`, `choices:[{id,label}]`),
`requestClosed`, `replyResult` (`ok`, `error: stale|failed`), `devices`, `internet`, `pairinfo`,
`loginToken`, `confirmRequired`, `confirmPending` (`checkCode`), `confirmRequest` (`confirmId`,
`action`, `checkCode`; устройствам), `confirmResult` (`allow`, `reason`, `retryAfterSec`),
`confirmClosed`, `error`. Закрытие с кодом 4401 — устройство отозвано / токен владельца перевыпущен.

### 7.2 Keeper ↔ мост (named pipe, JSON-строки)

Pipe `\\.\pipe\claude-bridge-<32 hex>`; сначала взаимное HMAC-рукопожатие с секретом сессии (D-11),
затем мост→keeper: `in`, `resize`, `kill`; keeper→мост: `hello`, `out`, `exit`.

### 7.3 Сайдкар туннеля → родитель (stdout, JSON-строки)

`ready` (ticket/node_id или port), `conn` (id/remote), `path` (id/path/addr/rtt_ms), `close` (id),
`id` (node_id), `error` (message).

### 7.4 HTTP-эндпоинты моста

`POST /pair` (код → токен; только основной порт, без авторизации), `POST /stt` (владелец или
устройство), `POST /hook` (токен хука своей сессии), `GET /health` (владелец или устройство),
`GET /?ott=…` (вход браузера; loopback, основной порт), статика (владелец или устройство).

### 7.5 UDP-обнаружение

Телефон → broadcast `CLAUDE_BRIDGE?` на `:8791`. Мост → unicast `{claudeBridge, port, fp}`
(только частным адресам, без имени ПК).

## 8. Модель безопасности (сводка)

Модель угроз — D-8: личный ПК, одна учётная запись. Вредоносная программа под учётной записью
владельца — вне модели.

| Угроза | Защита |
|---|---|
| Перехват трафика (MITM) | TLS с пиннингом SHA-256 отпечатка у телефона, `claude-mobile` и хука (M-8); доверие только по отпечатку, без отпечатка — никому (L-17) |
| Подмена ПК при сопряжении | Только QR: отпечаток вне канала, код не уходит на адрес из обнаружения (H-2) |
| Веб-страница в браузере ПК → мост (CSWSH, H-1) | Токен владельца вместо доверия по адресу; allowlist `Origin`; HttpOnly-cookie браузерного токена, вход по одноразовой ссылке |
| Агент выпускает код сопряжения / включает интернет (M-6) | Подтверждение человеком: консоль для первого телефона, затем только сопряжённый телефон с контрольным кодом и паузой после отказа (D-13, D-22) |
| Агент «подтверждает сам себе» | Токены устройств на ПК — только SHA-256 (D-15.7); `phoneRequired` закрывает консольный путь навсегда |
| Агент получает права владельца без чтения файлов | `--open` печатает ссылку и `--qr`/`--device` работают только в интерактивной консоли (D-18.2) |
| Флаги агента с телефона (M-7) | Телефон передаёт только id опций адаптера (P-3) |
| Доступ к pipe keeper'а по SMB | Взаимное HMAC-рукопожатие с секретом сессии (D-11) |
| Скрытый хвост команды в запросе разрешения | Очистка невидимых/bidi символов, «начало…конец» (D-19.2) |
| Ответ агенту с заблокированного телефона (M-4) | `setAuthenticationRequired(true)` на API ≥ 31; на API < 31 без «Всегда» |
| Кнопка старого уведомления отвечает новому запросу (C-1) | Значимые поля PendingIntent — в data-URI; уведомления прошлого процесса снимаются |
| Коллеги в офисной сети (P-7) | Мост слушает loopback и один LAN-адрес; маяк и mDNS без имени ПК; правила брандмауэра только для профиля «Частная» |
| Тайминг-атаки | Сравнение токенов и кодов за постоянное время |
| Перебор кода сопряжения | 5 попыток с адреса → блок 15 мин, 50 на код, код одноразовый, 10 мин |
| Падение моста от некорректного входа (M-2, L-1, L-2, M-3) | Проверка типов всех входов, авторизация до апгрейда WS, `maxPayload`, предел клиентов |
| Любой узел интернета → порт моста | Туннель fail-closed без allowlist; allowlist NodeId устройств, перепроверка на каждый поток |
| Кража p2p-ключа подменой пути | Windows: `FILE_FLAG_OPEN_REPARSE_POINT`, отказ от точек повторного анализа; Android: `O_NOFOLLOW` + операции по fd |
| Секреты в рабочей копии git (M-1) | Каталог данных в `%LOCALAPPDATA%`, `.gitignore` как страховка (в т.ч. `*.jks`, `*.keystore`, `dist/`) |
| Кража токена через XSS в WebView | Токен подставляет нативный ws-прокси; странице — только nonce запуска |
| Чужое приложение на телефоне → прокси | nonce запуска, сверка за постоянное время; входящие `Cookie`/`Authorization` выбрасываются |
| Утечка экрана телефона | `FLAG_SECURE`, биометрия с повторным запросом после гашения экрана, `VISIBILITY_SECRET` |
| Подмена APK | Release подписан ключом команды; SHA-256 сертификата — в README, SHA-256 артефактов — в `SHA256SUMS.txt`; `debuggable false` (M-5); wrapper Gradle с `distributionSha256Sum` (S-1) |

## 9. Сборка и запуск

### 9.1 Мост (ПК)

```powershell
powershell -ExecutionPolicy Bypass -File .\install.ps1 [-Firewall]   # установка / обновление
cd bridge; npm test                                                   # тесты (node:test)
node server.js                                                        # ручной запуск в консоли (отладка)
```

Изолированный запуск для тестов: `CLAUDE_BRIDGE_HOME` (каталог данных),
`CLAUDE_BRIDGE_LISTEN_PORT`, `CLAUDE_BRIDGE_TEST=1` (без mDNS, QR и файлового лога; также
`CLAUDE_BRIDGE_TEST_COOLDOWN_MS`, `CLAUDE_BRIDGE_TEST_IFACES`, `CLAUDE_BRIDGE_TEST_REPICK_MS`).

### 9.2 Туннель (Rust)

`tools/release.ps1` (`-SkipApk` — без APK): ПК — `cargo build --release --locked` →
`bridge\bin\claude-tunnel.exe` и `dist\`; Android — NDK 28 (`clang.exe
--target=aarch64-linux-android26` как компилятор C и компоновщик) →
`android\app\src\main\jniLibs\arm64-v8a\libclaudetunnel.so`. Без NDK шаг Android пропускается с
предупреждением (оно же — в `RELEASE_NOTES.md`); `-SkipAndroidTunnel` пропускает его явно. Нужны
Rust-targets `x86_64-pc-windows-msvc` и `aarch64-linux-android`.

### 9.3 Приложение (Android)

```powershell
cd android
.\gradlew.bat assembleDebug          # preBuild синхронизирует web-assets и xterm из bridge/
.\gradlew.bat testDebugUnitTest      # JVM-тесты (§5.7)
```

Нужен JDK 17 (`JAVA_HOME`) и Android SDK (`android/local.properties`). Wrapper — официальный
Gradle 8.7 с `distributionSha256Sum`. Release (`assembleRelease`) подписывается ключом команды из
свойств Gradle `cbReleaseStoreFile` / `cbReleaseKeyAlias` / `cbReleaseStorePassword` /
`cbReleaseKeyPassword` (передаёт `tools/release.ps1` через `ORG_GRADLE_PROJECT_*`); без них —
`app-release-unsigned.apk`. `debuggable false` задан явно (M-5).

### 9.4 Релиз

`tools\release.ps1 -KeystorePath <ключ> [-KeyAlias claude-bridge-team]` → `dist\` (каталог
пересоздаётся, в `.gitignore`): `claude-tunnel.exe`, `libclaudetunnel.so` (при наличии NDK),
`ClaudeBridge-<versionName>.apk`, `SHA256SUMS.txt`, `RELEASE_NOTES.md` (коммит, версии инструментов,
SHA-256 файлов и сертификата подписи). Проверки сценария: `aapt dump badging` без
`application-debuggable`, `apksigner verify --print-certs`. Пароль ключа вводится интерактивно и
передаётся только процессу Gradle (`--no-daemon`), затем стирается из окружения. Ключ команды и его
резервная копия — у владельца репозитория, вне репозитория. Канал распространения — GitHub
Releases форка `Aleksei-Dobrynin/agent-bridge-windows` (D-25.1).

## 11. Ключевые сквозные потоки

**Сопряжение:** `claude-mobile --qr` → мост просит подтверждение (консоль `[y/N]` для первого
телефона или `confirmRequest` с контрольным кодом на сопряжённом) → `pairinfo` → QR в консоли →
телефон сканирует → `POST /pair` с пиннингом `fp` → токен (на ПК — только его SHA-256) →
`BridgeStore` → сервис подключается по WSS; остальным устройствам — уведомление.

**Открытие терминала в приложении:** MainActivity грузит `http://127.0.0.1:38471` → `app.js`
зовёт `AndroidApp.wsUrl()` → WebSocket на `ws://127.0.0.1:38472/ws?cbnonce=…` → LocalGateway
сверяет nonce, подставляет токен и `Origin`, открывает TLS к мосту → `sessions`/`scrollback` →
xterm рисует.

**Запрос разрешения (Claude Code):** диалог в TUI → хук `PermissionRequest` → `POST /hook` →
адаптер `claude` → `notify{request, choices}` → уведомление с кнопками → «Да» (с разблокировкой) →
`reply{once}` → адаптер пишет `1` в PTY → `replyResult ok`, `requestClosed`. Для opencode —
`permission.asked` из SSE → тот же путь → ответ через API сервиса.

**Подтверждение операции владельца:** `claude-mobile --device` → `i` → `setInternet` → мост:
`confirmPending{checkCode}` в консоль, `confirmRequest{checkCode}` устройствам → человек сверяет код
и нажимает «Разрешить» → `confirm{allow:true}` → туннель включается, `confirmResult`.

**Голос:** долгое нажатие «отправить» → `MediaRecorder` → `POST /stt` → `stt.py` → текст в поле или
сразу агенту.

**Уход из сети ПК:** ПК не виден в LAN > 15 с → BridgeService поднимает `claude-tunnel connect` по
сохранённому `nodeTicket` → iroh до `listen` на ПК (allowlist NodeId) → `wss://127.0.0.1:<порт
туннеля>` → QUIC → loopback-порт 8792. Возврат в LAN — переподключение по прямому пути.

**Отсоединение `claude-mobile`:** `Ctrl+\` → пакет не пересылается агенту → `CONSOLE_RESET` в
консоль (режимы агента выключены, курсор на месте) → выход; сессия живёт в keeper'е.

## 12. Известные ограничения

**Модель и поведение:**

- **Граница каталога для устройств (D-21):** сессия устройства с каталогом вне `projects`
  запускается в `defaultCwd`; настоящая граница возможностей устройства — набор опций адаптера: с
  опцией `skipPermissions` агент не ограничен своим каталогом.
- **Подтверждение на телефоне не защищает от агента, который правит файлы моста и перезапускает
  его (D-22.1):** это эквивалент вредоносной программы под учётной записью пользователя (вне D-8).
  Агент той же учётной записи может прочитать `owner.token` и meta сессий (D-16.3).
- **Claude Code (D-23.7):** «готово» может прийти раньше окончания фонового субагента (O-2); после
  рестарта моста экран TUI может восстановиться только после следующей перерисовки (O-5, гипотеза).
  После рестарта моста при открытом диалоге разрешения кнопок нет — уведомление информационное
  (D-23.4).
- **Веб-клиент, диалог подтверждения (D-22.5):** при двух одновременных подтверждениях владельца
  диалог показывает последнее (первое вернётся после переподключения).
- **Веб-клиент, полоса запросов (D-24):** в `#reqbar` видны кнопки одного (верхнего) запроса,
  остальные — счётчиком «+N»; кнопки активны через 500 мс после смены верхнего запроса.
- **`generic`** — только зеркало: без статусов, уведомлений и кнопок ответа.
- **Android < 12 (API < 31):** без кнопки «Всегда»; подтверждение операций владельца — только в
  открытом приложении (M-4, D-15.10).
- **Хук Claude Code в пользовательских настройках (P-6)** запускает `node` на каждое событие в
  каждой сессии Claude на ПК; вне сессий моста хук сразу выходит.
- **Мост работает только в сеансе пользователя** (задача Планировщика или ярлык автозагрузки, не
  служба): до входа в Windows мост недоступен.
- **Брандмауэр:** корпоративные политики могут запрещать правила — тогда остаётся только туннель
  (P-4). Профиль сети Wi-Fi на ПК должен быть «Частная».
- **Только Windows-хост (D-9).**

**Состояние проверки и сборки (2026-10-31):**

- **Android-туннель не собран:** `libclaudetunnel.so` требует Android NDK (подплан 4, задача 9 —
  установка только после явного согласия пользователя). APK без неё работает только по локальной
  сети; интернет-доступ с телефона недоступен.
- **Сценарии на телефоне не выполнены:** 16 ручных сценариев подплана 3 (задача 11) — уведомления с
  кнопками, разблокировка, подтверждения, QR-сопряжение, прокрутка, Origin шлюза и др. — проверены
  только тестами (JVM, node) и отладочной сборкой, на реальном устройстве не проходились.
- **Release-APK ключом команды ещё не собран** (подплан 4, задача 10 — у владельца ключа): в README
  вместо SHA-256 сертификата подписи — заглушка `{{APK_CERT_SHA256}}`; подпись проверена только
  временным ключом.
- **Установка на реальном ПК** (подплан 4, задача 16) не выполнялась: мелькание окна консоли при
  автозапуске и регистрация задачи без прав администратора не проверены (запасные пути — D-25.3,
  D-25.4).
