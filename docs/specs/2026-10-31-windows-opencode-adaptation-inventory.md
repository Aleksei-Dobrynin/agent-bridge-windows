### D-7. Пути — единый платформо-зависимый модуль `paths.js` — ✅ accepted

| Поле | Значение |
|---|---|
| Решение | Вся работа с путями моста — в одном модуле: канонизация через `fs.realpathSync.native`; проверка вложенности через `path.relative` (а не `startsWith`), корректно для разных дисков и корня диска; на win32 сравнение без учёта регистра; для `cwd` с телефона отклоняются UNC (`\\server\share`), `\\?\`, `\\.\` и пути относительно диска (`C:foo`); в конфиге раскрываются `~` и `%VAR%`, принимаются `/` и `\`. | Уже совершено | — |

### D-20. Переподключившийся клиент получает открытые запросы — ✅ accepted (делегировано, 2026-10-31)

При подключении WS-клиента мост повторно шлёт ему `notify{event:'request', requestId, choices, …}` по всем ожидающим запросам (как для `confirmRequest`); поле `pending` в `sessions` не вводится. Причина: телефон, переподключившийся после уведомления (или запрос, найденный ресинхронизацией после рестарта моста), иначе не видит кнопок.

### D-21. Граница каталога для устройств — ✅ accepted (делегировано, 2026-10-31)

`defaultCwd` — неявно разрешённый корень: сессия устройства с каталогом вне `projects` запускается в `defaultCwd` (поведение OT-11 сохранено — пользователь отложил его как устраивающее). Настоящая граница возможностей устройства — **набор опций адаптера**: при опции `skipPermissions` агент не ограничен своим каталогом. Причина: ревью задач 10–13 (I-1); отказ устройству (вариант B) противоречил бы решению пользователя по OT-11.

### P-2 (OT-2). Интерфейс адаптера — ✅ accepted

```js
// bridge/agents/<id>.js
module.exports = {
  id: 'claude', name: 'Claude Code',
  options: [ { id: 'resume', label: 'Продолжить беседу', type: 'bool' },
             { id: 'skipPermissions', label: 'Без запросов разрешений', type: 'bool' } ],
  // что запустить в keeper: основной процесс в PTY + вспомогательные процессы
  spawnSpec({ cwd, options, session }) -> { command, args, env, helpers: [{ command, args, env }] },
  events: 'hook',                                  // 'hook' | 'sse' | 'none'
  onHook(session, payload) -> [Event],             // для events:'hook'
  subscribe(session, emit) -> unsubscribe,         // для events:'sse'
  reply(session, request, decision) -> Promise,    // decision: 'once' | 'always' | 'reject'
};
// Event: { kind:'status', status:'working'|'waiting'|'idle' }
//      | { kind:'request', requestId, message, choices }   // запрос разрешения
//      | { kind:'requestClosed', requestId }
//      | { kind:'notify', message }                         // «агент закончил» и т.п.
```

|---|---|---|---|
| `claude` | `claude` + флаги из `options` | `hook`: `Notification` → `request` (requestId генерирует мост); `PostToolUse` / `UserPromptSubmit` → `requestClosed` + `working`; `Stop` → `idle` + `notify` | клавиши: `once`→`1`, `always`→`2`, `reject`→Esc (как сейчас в `BridgeService.java:820`) |

| `generic` | `command` / `args` из конфига | `none` | раскладка клавиш из конфига или без кнопок |
